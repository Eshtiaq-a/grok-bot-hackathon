        Protocol

        Payment clears only after the platform agrees.

        A seller publishes a signed offer. The buyer agent verifies each claim with CreateOS before any money moves.

        1. 01

          Publish

          Package an open-source tool in a CreateOS sandbox, harden egress, seal acceptance tests, pause the parent, and sign an Ed25519 offer manifest.

        2. 02

          Verify

          Inspect parent status and egress with a short-lived CreateOS token. Compare digests and claims to the signed manifest before calling buy.

        3. 03

          Pay

          Matching offers settle through Stripe Machine Payments (HTTP 402). Any mismatch creates zero PaymentIntents.

        4. 04

          Execute

          Fork a worker from the verified parent, re-check integrity, run the job, keep a receipt, and refund automatically if post-pay checks fail.

        Built for

        Teams that let agents spend on tools.

        Polygraph sits between the buyer agent and payment rails so a stranger’s sandbox cannot be paid until the platform confirms it.

        • Agent wallets

          Gate disbursement on platform-verified claims so agents never fund a sandbox that isn’t what it signed.

        • Tool marketplaces

          Verify every listing against CreateOS, then auto-refund when a seller changes the artifact after sale.

        • Honest sellers

          Sealed suites, locked networks, and signed offers give buyers cryptographic reasons to trust a first listing.

        Integrity lab

        Prove the verifier catches dishonest offers.

        Operators can simulate integrity failures against a live gateway. These controls stay off the critical purchase path unless explicitly enabled.

        Simulate a false claim

        Fork the seller’s paused parent, alter egress or a single artifact byte, and publish a still-valid signature so the buyer’s CreateOS checks can refuse it.

        Requires DEMO_TAMPER=1 on the gateway. Disabled by default in production configs.

        Receipts

        Every completed job leaves an auditable trail.

        Each id points at records the seller cannot edit: the Stripe PaymentIntent, the CreateOS worker and parent, and sha256 digests of the input and output.

        • Worker forked_from matches the parent named in the signed offer.
        • Tool digest is recomputed inside the worker, not taken from the seller.
        • The worker is destroyed when the job completes or refunds.
